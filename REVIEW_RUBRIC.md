# Cami Review Rubric

| Area | Weight | What to look for |
|---|---:|---|
| Working implementation | 25% | Endpoint works, expected categories returned, build/CI issue fixed, no obvious regressions |
| Code quality | 25% | Simple, maintainable, readable, no unnecessary complexity |
| Tests | 20% | Meaningful happy path and edge case tests |
| AI usage and judgement | 15% | Clear AI_USAGE.md, sensible use of AI, evidence of review/rejection |
| Documentation | 10% | README is useful and accurate |
| Product thinking | 5% | Good assumptions, pragmatic trade-offs |

## Suggested final PR walkthrough questions

- Why did you choose this implementation?
- What did AI help with?
- What did AI get wrong?
- What trade-offs did you make because of the timebox?
- What edge cases did you test?
- What would you improve with another day?
- How would you deploy this in a real service?
